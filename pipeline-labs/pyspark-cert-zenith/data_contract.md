# Zenith Online Synthetic Data Generator - Output File Schemas

This document describes the schema of the files generated by the `data_generator.py` script for the Zenith Online Spark certification project.

---

## 1. Customer Profiles (CSV)

**File:** `customer_profiles.csv`
**Location:** `<RAW_BATCH_CUSTOMERS_PATH>/customer_profiles.csv`

| Column Name | Type   | Description                              |
| ----------- | ------ | ---------------------------------------- |
| customer_id | int    | Unique identifier for the customer       |
| signup_date | string | Date the customer signed up (YYYY-MM-DD) |
| location    | string | Customer's city/location                 |

---

## 2. Product Details (Parquet)

**File:** `product_details.parquet`
**Location:** `<RAW_BATCH_PRODUCTS_PATH>/product_details.parquet`

| Column Name  | Type   | Description                              |
| ------------ | ------ | ---------------------------------------- |
| product_id   | long   | Unique identifier for the product (1-500); stored as a 64-bit integer (pandas `int64`), so Spark reads it as `long` |
| product_name | string | Unique name: adjective, a noun that fits the category, model code (e.g., `Rustic Bookcase Z003`) |
| category     | string | Furniture, Home Decor, Electronics or Office Supplies |
| price        | double | Product price in USD, inside the category's band: Furniture 89.00-899.99, Home Decor 15.50-249.99, Electronics 29.99-599.99, Office Supplies 15.50-79.99 |

---

## 3. User Events Stream (JSON)

**Files:** `events_<timestamp>.json`
**Location:** `<RAW_STREAMING_PATH>/events_*.json`
**Each file is JSON Lines: one event object per line.**

| Field Name      | Type   | Description                                                |
| --------------- | ------ | ---------------------------------------------------------- |
| event_id        | string | Identifier of the event (UUID); a client retry repeats it exactly |
| event_timestamp | string | Event timestamp in ISO 8601 format (UTC)                   |
| user_id         | int    | ID of the customer who performed the event (1-1,000, or 1001-1050 for a late sign-up) |
| event_type      | string | Type of event:`view_product`, `add_to_cart`, or `purchase` |
| product_id      | int    | ID of the product involved in the event (1-500, or 501-505 for a delisted product) |
| session_id      | string | Identifier of the tracking call's session (UUID; the generator issues a new one per event, so it carries no session grouping) |

---

**Notes:**

- All IDs (`customer_id`, `product_id`, `user_id`) are integers and share one ID space across files, so the events join to the two dimension files, apart from the planted issues below.
- The event stream intentionally introduces data skew across all event types: 75% of events (views, add-to-carts and purchases alike) go to the 5 products in `POPULAR_PRODUCT_IDS` (101, 210, 315, 420, 55).
- Planted issue, client retries: about 1% of events (500 per file) are re-sent as exact copies, same `event_id` and same `event_timestamp`, as a tracking SDK does when a beacon call times out. The Silver de-duplication removes them.
- Planted issue, late sign-ups: about 0.5% of events (250 per file) carry a `user_id` from 1001-1050, accounts created after the nightly CRM export, so `customer_profiles.csv` does not have them yet. The Silver left join keeps them with a null region.
- Planted issue, delisted products: about 0.2% of events (100 per file) carry a `product_id` from 501-505, products removed from the catalog export after the event fired. The Silver inner join drops them, because they cannot be priced.
- The batch files are a single file each, rewritten in place on every run of `00_Setup_Environment` (the generator is seeded, so it is the same 1,000 customers and 500 products), while the event stream files are generated once per run of `00_Setup_Environment`: one new file per run, 50,500 lines per file (50,000 events plus 500 retried copies), with timestamps within the 30 seconds before the run.
- The files land in the `zenith_online.00_landing` volumes, at the paths defined in `notebooks/variables.py`: `RAW_BATCH_CUSTOMERS_PATH` (`/Volumes/zenith_online/00_landing/batch/customers`), `RAW_BATCH_PRODUCTS_PATH` (`/Volumes/zenith_online/00_landing/batch/products`) and `RAW_STREAMING_PATH` (`/Volumes/zenith_online/00_landing/streaming/user_events`).
