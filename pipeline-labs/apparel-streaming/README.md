## 1. Context and Goal

Welcome to the Apparel Retail 360 project! You are the data engineer at LoomLane Outfitters, a fictional 5-store apparel chain that runs its tills, loyalty program, product catalog and store records on separate systems. Store managers get yesterday's sales by email at noon, merchandising cannot see which items sell, and marketing ranks customers from a spreadsheet. Your job: one pipeline that turns the four raw feeds into three tables they can use on Monday morning: daily sales per store, product performance, and customer spend.

Using Lakeflow Spark Declarative Pipelines (formerly Delta Live Tables / DLT), you will ingest raw data, progressively clean and transform it through a medallion architecture (Bronze, Silver, and Gold layers), and ultimately produce curated datasets ready for business intelligence and reporting.

Feel free to reach out to me if you have any questions. My contact details are available on dataengineer.wiki.

## 2. What You Will Practice

- Ingesting and processing continuous data streams.
- Applying and managing data quality expectations.
- Implementing a medallion architecture in a Lakeflow pipeline.
- Handling historical data changes using Slowly Changing Dimensions (SCD Type 2).
- Creating business-ready, aggregated tables for analytics.

## 3. Architecture

- Databricks Free Edition
- Synthetic streaming data (generated by `dlt/data_generator.py`)
  - It plants realistic data quality issues: returns, sign errors, typos, missing values and unmapped codes ([SyntheticDataGenerator.md](SyntheticDataGenerator.md) lists them)
  - It generates 4 tables (a fact sales table, and 3 lookup tables - stores, customers, products)
  - On its first run it backfills 30 days of sales history, then streams live.
  - Backfill: 40 sales per store per day; live: 500 sales every 30 seconds, so today's rows dwarf any backfilled day ([SyntheticDataGenerator.md](SyntheticDataGenerator.md) has the details).
- Lakeflow pipeline
  - You'll create a Lakeflow pipeline to ingest, clean and aggregate raw data.
  - The pipeline is organized into layers:
    - **Bronze layer** (`dlt/01_bronze.py`) - Raw data ingestion
    - **Silver layer** (`dlt/02A_silver.py`, `dlt/02B_silver.py`, `dlt/02C_silver.py`, `dlt/02D_silver.py`) - Cleaned and transformed data
    - **Gold layer** (`dlt/03_gold.py`) - Business-ready aggregations
  - At the end, your pipeline graph shows 20 datasets, left to right:
    - **Bronze** (streaming tables): `bronze_sales`, `bronze_customers`, `bronze_products`, `bronze_stores`, each read from its landing folder.
    - **Silver, cleaning** (views, one per bronze table): `sales_cleaned_stream`, `customers_cleaned_stream`, `products_cleaned_stream`, `stores_cleaned_stream`.
    - **Silver, tables** (streaming tables): `silver_sales_transactions` and `silver_returns_transactions`, both fed by `sales_cleaned_stream`; `silver_customers`, `silver_products`, `silver_stores` (SCD Type 2), each fed by its cleaned view.
    - **Silver, current state** (views): `silver_customers_current`, `silver_products_current`, `silver_stores_current`, each over its SCD2 table.
    - **Gold**: the streaming table `denormalized_sales_facts`, fed by `silver_sales_transactions` and the three current views; the materialized views `gold_daily_sales_by_store`, `gold_product_performance` and `gold_customer_lifetime_value`, each fed by `denormalized_sales_facts` and the current view that supplies its names (stores, products, customers).

## 4. Prerequisites

- Intermediate PySpark (DataFrame API). All tasks are written in Python.
- Know what a streaming table and a Delta table are; the lab teaches Lakeflow expectations, AUTO CDC and stream-static joins.
- Intermediate Databricks knowledge. Junior engineers can finish it too, but expect to lean on the solutions more often. If you need help, feel free to copy code snippets from the solution file (`final_code/final_dlt.py`) to run and observe the Lakeflow pipeline.
- Time: about 7.5 hours for a mid-level engineer working from the text (setup and data generation, then 20 tasks); plan it as three sessions: setup and bronze, silver (the longest, a little over half the lab), gold.

## 6. Project Structure

The project is organized as follows:

### `dlt/` folder - Main working directory

This folder contains everything you need to complete the lab:

- **Environment Setup:**

  - `environment_setup.ipynb` - Notebook to set up Unity Catalog (catalogs, schemas, volumes)
  - `environment_maintenance.ipynb` - Maintenance utilities for the environment
  - `variables.py` - Configuration file for catalog names, paths, and other settings

- **Data Generation:**

  - `data_generator.py` - Synthetic data generator that creates realistic streaming data

- **Lakeflow Pipeline Files (Your Tasks):**

  - `01_bronze.py` - Bronze layer: Raw data ingestion from the landing folders (Tasks 1-4)
  - `02A_silver.py` - Silver layer: cleaned views with data quality expectations for all four streams (Tasks 5-8)
  - `02B_silver.py` - Silver layer: SCD Type 2 dimensions for customers, products and stores (Tasks 9-11)
  - `02C_silver.py` - Silver layer: sales and returns fact tables (Tasks 12-13)
  - `02D_silver.py` - Silver layer: current-version views of the three dimensions (Tasks 14-16)
  - `03_gold.py` - Gold layer: Business-ready aggregations and analytics (Tasks 17-20)

  **Note:** Each file contains tasks with requirements and a "Solution Is Below" section for reference.

### `final_code/` folder - Reference materials

- `final_dlt.py` - Complete solution for the entire pipeline when you need a full reference

### Documentation

- `README.md` - this file: project overview
- `ProjectPlan.md` - Step-by-step instructions and tasks
- `SyntheticDataGenerator.md` - Details about the data generator and schemas
- `data_contract.md` - every table your pipeline must produce, with its columns, types and keys

## Appendix: Where this project meets the Databricks Data Engineer Associate exam

This lab is not full exam prep. It gives hands-on practice with these objectives of the current exam guide (45 scored multiple-choice questions, 90 minutes, online or test center):

- **Data Ingestion and Loading**: incremental streaming reads into bronze streaming tables, lineage columns from the `_metadata` column.
- **Data Transformation and Modeling**: the medallion architecture, expectations (warn, drop, fail), SCD Type 2 with AUTO CDC (`create_auto_cdc_flow`), streaming tables vs materialized views, stream-static joins and aggregations.
- **Governance and Security**: Unity Catalog catalogs, schemas and volumes (set up by `environment_setup.ipynb`).

Not covered here: Lakeflow Jobs, CI/CD with Declarative Automation Bundles, Spark UI and query troubleshooting, permissions, Delta Sharing. Check the official exam guide for the full outline: https://www.databricks.com/learn/certification/data-engineer-associate
